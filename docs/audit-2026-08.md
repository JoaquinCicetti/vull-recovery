## ⚠️ Mobbex is parked

The Mobbex account has not been enabled, so online card payments are **off**. As of
this audit `NEXT_PUBLIC_MOBBEX_ENABLED` (default `false`) hides the "Pagar online"
button entirely — previously it rendered as the *primary* call to action on both the
turno and pack-purchase screens and always failed, because `create-payment` answers
`503 "Pagos online no configurados"` without `MOBBEX_API_KEY`. Bank transfer + receipt
is now the visible primary path.

Everything Mobbex-specific below is **documented but deliberately not implemented**,
grouped in [§7](#7-mobbex--on-hold). Re-open that section before switching the flag on;
several of those items are P0-class and **must** land before the first real card
payment.

## 1. P0 — fixed 2026-08-24

### P0-1 · Every credit RPC was callable from the browser
`supabase/migrations/20260701120000_packs_credits.sql:252-256`

The migration ended with `revoke execute … from anon, authenticated`. That does not
remove the privilege: PostgreSQL grants `EXECUTE` to the pseudo-role **PUBLIC** on
every function at creation, and a role-targeted `REVOKE` never strips a PUBLIC grant.
`anon` and `authenticated` kept EXECUTE by inheritance. (`create or replace function`
preserves the ACL, so recreating `grant_pack_credits` in `20260702130000` changed
nothing either.)

All five are `SECURITY DEFINER`, sit in the PostgREST-exposed `public` schema, and take
the acting user as a **parameter** rather than reading `auth.uid()`. With only the
publishable key that ships in the browser bundle:

```
POST /rest/v1/rpc/adjust_credit
     {"p_user":"<any uid>","p_service":"<any>","p_delta":9999,"p_note":"","p_admin":null}
        → unlimited free sessions
POST /rest/v1/rpc/book_with_credit
        → a `confirmed` booking for any user at any hour, bypassing working hours,
          the 60-minute lead time, the pack price guard and the use_credit gate
POST /rest/v1/rpc/credit_balance    → read anyone's balance
```

**Fixed:** `supabase/migrations/20260824120000_revoke_public_rpc.sql` revokes from
`public, anon, authenticated` and ends with a `do $$` block that re-asserts the result
via `has_function_privilege()`, so a future regression fails the migration instead of
silently reopening the hole. `my_credit_balances()` (parameterless, `auth.uid()`-scoped)
keeps its grant. The edge functions are unaffected — the service-role key bypasses
privilege checks.

> **Deploy note:** this needs `supabase db push`. Until it is applied the hole is live.
> Verify with
> `select has_function_privilege('anon','public.adjust_credit(uuid,uuid,int,text,uuid)','execute');`
> → must be `false`.

### P0-2 · A payment could be marked paid for a turno the client does not have
`admin-payment/index.ts:59-79`, `admin-booking/index.ts:52,82`

`approve` flipped the payment to `approved` first, then ran the bookings UPDATE **with
its error discarded**, then emailed the confirmation unconditionally — and guarded only
on `status !== 'confirmed'`, so `cancelled` / `expired` / `no_show` rows were resurrected.

*Scenario:* a client uploads a transfer receipt; the 20-minute hold lapses and the
booking flips to `expired`; someone else books the slot. The payment is still in the
admin queue (it filters on `provider='manual' AND status='pending'` only). The admin
clicks **Aprobar** → the UPDATE violates `bookings_no_overlap` (23P01) → error dropped →
payment reads `approved`, the booking is still `expired`, its slot belongs to somebody
else, and the client receives "Tu turno está confirmado ✓".

**Fixed:** confirm the booking **first** and only settle the money if that succeeded;
require `payments.status = 'pending'` (re-approving a settled row used to re-send mail
and, for a rejected pack, grant credits after the fact); restrict confirmation to
`pending`/`awaiting_payment` and re-assert it in the UPDATE's `WHERE` (the hold can lapse
between the read and the write); return a 409 the admin actually sees, telling them to
reprogram or refund. `admin-booking confirm` now settles only `provider='manual'` rows
(it used to approve an abandoned online checkout too) and `no_show` is likewise guarded.

### P0-3 · Booking errors were invisible to the client
`app/reservar/[serviceId]/booking-flow.tsx:186-187`

```ts
setError(await readError(error));  // the server's Spanish message
reload();                          // → reload() line 105: setError(null)
```

`reload()` clears the error synchronously before its first `await`, so the message never
survived to a paint. Every failure — 409 slot taken, 409 one-turno-per-day, 409 no
credits, 429 throttle — showed as a grid flicker and a lost selection. Two phones racing
for 10:00: the loser learns nothing and retries blindly.

**Fixed:** `reload({ keepError: true })`; an explicit error when a 200 arrives without
`booking.id` (it silently no-op'd and re-enabled the button, inviting a double-book); the
message moved **above** the sticky confirm bar (on mobile it rendered underneath it,
i.e. exactly where the bar sits) with `role="alert"`; and a **Reintentar** button on the
availability-failed state, which had no recovery path despite `reload()` existing.

### P0-4 · The homepage had no failure floor
`components/experience/scene.tsx`, `experience-client.tsx:181-233`, `app/` (no error files)

There was no `error.tsx`, `not-found.tsx` or `global-error.tsx` anywhere. `<Canvas>`
builds its `WebGLRenderer` in a layout effect and `useGLTF` **throws** on a 404 — neither
is caught by `<Suspense>` — so no WebGL, a blocklisted GPU, a stale HTML shell pointing
at a deployed-away chunk, or a missing GLB unmounted the React root and replaced the
entire homepage (hero, CTAs, plans — the whole conversion path) with Next's English
"Application error".

Worse, the wheel/touch handlers `preventDefault()` while `scrollY <= 2` regardless of
whether the scene ever rendered, and reaching `#planes` costs ~1,176 wheel px / ~770
touch px **plus** a 420/260 px sticky anchor. A failed scene therefore produced a black
screen the visitor had to fight ~1,600 px to escape. There was also no
`webglcontextlost` listener, so a thermal GPU reset left a permanently black hero.

**Fixed:**
- `components/experience/scene-boundary.tsx` — error boundary wrapping `<SceneLayer>`
  (fallback: the static hero) and `<Bath>` (fallback: spheres-only).
- `Scene` reports liveness via `onAlive`, set from `onCreated` and cleared on
  `webglcontextlost` (restored on `webglcontextrestored`). The scroll handlers consult it
  and step aside, so a dead scene can never trap the page.
- `StaticHero` — which was **dead code**, leaving `/` with nothing behind the canvas but
  `bg-black` — now renders underneath it, so a slow/paused/failed scene shows a
  photograph rather than a black rectangle.
- `app/error.tsx`, `app/not-found.tsx`, `app/global-error.tsx` in Spanish, inside
  `PageShell`, with real next actions.
- Space/arrow keys no longer stolen from a focused button or input.

### Also fixed: the two lint errors
`turno/[id]/page.tsx:52` called `Date.now()` during render (`react-hooks/purity`) — now
read once from a server-computed `nowISO`. `experience-client.tsx:128` set state inside
an effect (`react-hooks/set-state-in-effect`) to detect reduced motion; resolving it in
the `useState` **initializer** also closes a real perf bug: the first client render used
to fall through to the full branch, mounting `<SceneLayer>` and firing the ~1.3 MB scene
chunk + GLB preload *before* swapping to the fallback — so reduced-motion visitors paid
for a scene they never see. (A one-frame flash remains for them; see §5.)

## 2. P1 — money & booking correctness

- **`awaiting_payment` never expires.** Both lazy sweeps (`availability:29-33`,
  `create-booking:38-42`) filter `status='pending'` only, and nothing else transitions it.
  Per the owner's decision (2026-08-24) this **stays as-is**; the mitigation is an admin
  affordance — show "reteniendo desde hace Xh" on those rows so squatters can be cancelled
  by hand. Documented caveat: `docs/booking-invariants.md:55`.
- **An expired hold is still payable.** `create-payment` never checks `hold_expires_at`,
  and nothing on `/turno` expires the row — so the countdown renders
  "Se venció la reserva" *directly above a working "Pagar" button*
  (`hold-countdown.tsx:55-75`, `turno/[id]/page.tsx:44-50,79`).
- **Unchecked payment inserts**, `create-payment/index.ts:95,172`. The manual path still
  flips the booking to `awaiting_payment` and returns `{ok:true}` when the insert failed:
  the receipt is orphaned in Storage, nothing reaches the admin queue, and the slot is
  locked.
- **Rejecting a manual payment strands everything.** `admin-payment/index.ts:37-43` only
  touches the payment row: the booking stays `awaiting_payment` (holding slot and day),
  the client is never told, and a rejected **pack** keeps its granted credits — the
  `'revoke'` ledger reason exists in the schema and is written by no code path.
- **Reschedule notifies nobody** (`admin-booking/index.ts:93-149`). The row and the Google
  event move; the client shows up at the old time.
- **Cancelling a paid booking silently keeps the money.** `cancel-booking:79-87` and
  `calendar-poll:81-87` reject only `pending` payments; no refund obligation is recorded
  and the owner is not alerted.
- **Pack payments are unreadable in the verify queue.** The select embeds `bookings(...)`,
  which is `null` for a pack, so the row shows "Servicio — $X", client "—", no date
  (`app/admin/page.tsx:48,57-65`).
- **The admin list never updates after an action.** `useState(initialUpcoming)`
  (`admin-bookings.tsx:162`) ignores the refreshed prop `router.refresh()` delivers — the
  counter changes, the rows do not. The cancelled turno stays on screen with a green chip
  and live buttons; clicking again returns a 409.
- **Load-more is offset-based over a live filtered set** (`admin-bookings.tsx:175`), so a
  concurrent cancel makes page 2 skip a row and an earlier insert makes it duplicate one
  (React duplicate-key warning). Its `error` is discarded entirely (`:168`).
- Duplicate manual receipts: uploading N times creates N pending rows and N admin alerts;
  two approved pack rows double-grant (each has its own `payment_id`, so the idempotency
  index cannot help).
- `availability` ignores the bookings query error → on a DB failure it advertises **taken
  slots as free** (`:66-83`); a malformed uuid reports `404 "Servicio no disponible"`.
- `services_read` hides inactive services (`init.sql:154-155`), so deactivating a plan
  makes existing clients' `/turno` render "Servicio" and a total of **$0**.
- `refund_booking_credit` adds `+1` to an expired balance (which reads as 0) — the
  refunded session silently vanishes (`packs_credits.sql:198-202`).
- Admin reschedule inherits the client's 60-minute lead rule (`admin-booking:124`), so the
  owner cannot move a turno to 30 minutes from now — the exact walk-in case the override
  exists for. Rescheduling a `pending` booking never refreshes `hold_expires_at`, so the
  next sweep can expire the turno that was just moved.
- Service duration/price are unvalidated (`services-manager.tsx:31-38,151-153`): `600`
  silently yields zero slots forever, `5` yields 108/day, price `0` is accepted.
  `sort_order: initial.length` collides after any delete.
- `calendar-poll`: a 410 clears the sync token and returns, so every external deletion in
  the gap is lost permanently; the conflict alert names no booking; `cancelled_by` is left
  null.
- `keep-alive`'s `catch` is dead (supabase-js returns errors rather than throwing) — it
  answers `ok` while the database is down.

## 3. P1 — client UX that blocks or misleads

- **The OTP field is 8 boxes for a 6-digit code** (`login-form.tsx:143,154`;
  `config.toml:233` is `otp_length = 6`; the page copy promises "6 dígitos"), so
  `onComplete` auto-submit never fires and two empty boxes remain.
- Raw **English** Supabase errors in a Spanish UI (`login-form.tsx:44,78`,
  `profile-form.tsx:32`) — e.g. "For security purposes, you can only request this after 44
  seconds" (`max_frequency = 60s`), "Token has expired or is invalid".
- **No resend-code button** on the code step at all.
- **Turnstile is single-use and never reset**: the consumed token is replayed on the second
  send, which always fails. If `challenges.cloudflare.com` is blocked or the script never
  loads, `captchaToken` stays null and submit is refused with "Completá la verificación de
  seguridad" — **with no widget to complete and no escape**. Login becomes impossible.
- `/login?error=auth` is read by nobody and drops `next` (`auth/callback:23`,
  `login/page.tsx:9`). `next` is unvalidated → open redirect via `router.push(next)`.
- The **selected slot is lost across the login round-trip** (`booking-flow.tsx:139`); the
  stale `bookedDays` server prop after Back produces a phantom 409.
- `/mis-turnos` is ascending with every status mixed in (`:20`) — a returning client sees a
  years-old cancelled session first and today's turno off-screen. It is the header's
  primary link.
- `cancelled` / `expired` / `no_show` on `/turno` is a **dead end**: no "Reservar otro", and
  no mention that the credit was refunded (it was, server-side).
- `capitalize` on `fmtDateTime` produces **"Miércoles, 3 De Junio, 14:30"** — on the
  confirmation screen of a brand whose stated personality is "precise" (`turno:59`,
  `mis-turnos:52`, `booking-flow:280`, `admin-bookings:134`, `admin-payments:117`).
- The booking flow **auto-spends a credit** (`use_credit: credits > 0`) with no choice.
- **Phone normalization differs between the two writers**: `/cuenta` stores digits-only
  (required to match the WhatsApp webhook), the booking flow stores it raw and its
  placeholder encourages spaces — so first-time clients never match inbound WhatsApp.
- Push: the toggle saves `notify_push` and *then* reveals `PushManager`, so the user
  believes push is on with no permission ever requested; the `denied` state renders an
  **enabled** button that does nothing; `push-manager.tsx:58-59` registers the SW *before*
  `requestPermission()`, which breaks Safari/iOS user-activation; there is **no unsubscribe
  path**; the manifest ships only an SVG icon, which iOS ignores — and an installed PWA is
  the prerequisite for iOS Web Push, the entire reason the manifest exists; `sw.js` has no
  `pushsubscriptionchange` handler, so a rotated endpoint dies silently while the UI still
  says "activadas".
- Admin has no search or filter; "Recientes" shows the first 20 of a 21-day window with no
  load-more; cancelled **future** turnos are invisible everywhere; pending payments are
  capped at 50 with no page 2; `nowISO` is frozen at render so "No asistió" never appears
  without a manual reload; admin cancel never sends a reason (defeating the column added
  for it); service **Eliminar** is one-click with no confirm; `validity_days` has no UI, so
  every pack created from the admin never expires.
- `waLink()` returns `"#"` when the business number is unset — dead CTAs rather than a
  hidden one.

## 4. Performance

- **`/` eagerly loads three.js.** `import { useProgress } from "@react-three/drei"`
  (`experience-client.tsx:5`) is a synchronous dependency of the page's client entry, so
  the 371 KB three chunk and 84 KB gsap are `async:false` on the LCP route — ~730 KB eager
  vs 80 KB on `/mis-turnos`. The `dynamic(..., {ssr:false})` split correctly isolates
  everything else; this one import defeats it. Fix: deep-import `useProgress` (or move
  `LoadingScreen` inside the dynamic module) and dynamic-import gsap.
- **Two full-screen rAF particle canvases** on `/reservar`, `/comprar/*` and `/planes`:
  `AmbientBackground` (root layout) plus `PageShell ambient → LocalAmbient`, each painting
  42 arcs a frame with a per-dot `ctx.shadowBlur = 6` — a software blur — never paused when
  scrolled offscreen (only on tab-hide). That is the conversion path, on mobile. `resize`
  also re-seeds, so the dots visibly teleport on every mobile address-bar show/hide.
- `public/model-bath-2.glb` is **1.27 MB uncompressed** (no Draco/meshopt/KTX2) and gates
  the loading veil behind a 9 s timeout.
- `.surface-card` carries `backdrop-filter: blur(14px) saturate(1.15)` over a
  `background-attachment: fixed` body — 20 stacked layers in the admin list on a phone.
- Sequential server awaits where `Promise.all` applies: `/reservar` (service → bookings →
  balances, the hottest route), `/mis-turnos`, `/cuenta`, and `lib/credits.ts` (which also
  builds two separate clients).
- `plans.tsx` is `"use client"` + framer-motion for a staggered fade the existing
  `.stagger-children` CSS already does, on a grid with zero interactivity.
- The header logo is a **raster with `priority`** on every route — a preload competing with
  each page's real LCP — while the vector `logo.svg` sits unused by the UI.
- `/planes` serves a 1.07 MB and a 553 KB JPEG with no `quality` cap.
- The adaptive tier only lowers DPR; DoF is gated on `isMobile`, so a struggling low-end
  **desktop** keeps the pass mounted.
- `h-screen` (100vh) on the experience section while every other hero uses `svh` — on
  mobile Safari the scroll cue sits under the toolbar.
- `availability` is unauthenticated and performs a table-wide UPDATE plus an outbound
  Google freeBusy call per request — trivially abusable to burn quota.

**Dead code:** `InputOTPSeparator`; the `CreditBalance` type; `adjust_credit` (no endpoint
or UI — and the sharpest edge of P0-1); the dropzone's `key={JSON.stringify(src)}`, which

**Accessibility:** no `role="alert"`/`aria-live` on any error region outside the booking
flow; slot buttons lack `aria-pressed` and calendar days lack `aria-selected` (selection is

**The edge functions do not type-check under Deno 2.** `deno check` reports 7 errors, all

deploys without this check — but it means the one part of the codebase `tsc` cannot see is
currently unverified. Fix: type the buffers as `Uint8Array<ArrayBuffer>` (or `.slice()` into
a fresh `ArrayBuffer`) and add `deno check supabase/functions/**` to CI, which nothing runs
today.

**Correctness nits:** `mini-calendar` decides "today" in the browser's timezone while every
date string is salon-local; `booking_local_date()` and `touch_updated_at()` lack
`set search_path` (`booking_local_date` is baked into an index expression); `spheres.tsx`
lights the wrong instances during the flow phase, comparing against pre-flow positions.

**Copy & meta:** `hold-countdown.tsx:65` is a comma splice; "Pagar online (… transferencia
· QR)" sat 40 px above "Pagué por transferencia", two different meanings of the word
(moot while Mobbex is off). Only the root layout exports `metadata`, so **every** route is
titled "VULL" with no `metadataBase` and no OpenGraph — WhatsApp-shared links, the
product's primary channel, have no preview card. `/mis-turnos`'s empty state links `/`
(dropping the user into the WebGL scroll) instead of `/#planes`. No `loading.tsx` for
`/comprar/*`, `/login`, `/planes`, `/`. The `/reservar` skeleton does not match what
replaces it, so the page visibly jumps. `Badge`'s base is `rounded-4xl` — a pill — which
`DESIGN.md` explicitly forbids; every consumer overrides it.

**Env & doc drift:** `.env.example` documents `GMAIL_USER`/`GMAIL_APP_PASSWORD` while the
code uses `RESEND_API_KEY`/`EMAIL_FROM`, and omits `CALENDAR_POLL_TOKEN` entirely; the
hold default is 20 in code and 10 in the docs; `docs/architecture.md`'s function table
omits `cancel-booking`, `admin-booking` and `calendar-poll`, and its lifecycle line omits

## 6. Verified sound — do not re-check

The no-overlap `EXCLUDE` and the per-day partial unique index are genuinely DB-enforced and
race-safe, with the active-status set consistent across the constraint, both sweeps, and
every edge function; 23P01/23505 are mapped to 409 with the right Spanish strings.
`book_with_credit` cannot leak or double-spend — the conditional `update … where remaining
> 0` takes the row lock and the insert shares its transaction, so a rejected slot rolls the
decrement back. Grant/refund idempotency via the two partial unique indexes on
`credit_ledger` is correct. The June privilege-escalation fix (S1) is properly closed,
including the later `notification_prefs` migration re-granting only its two columns.
`is_admin()` is `SECURITY DEFINER` with a fixed `search_path`, and all three admin
endpoints re-check it server-side through the service-role client rather than trusting the
JWT. CORS is a real allow-list with `Vary: Origin`; webhooks emit no ACAO. WhatsApp's
`X-Hub-Signature-256` check and `calendar-poll`'s token both fail closed. The RLS read
surface is tight — `calendar_sync` has RLS on with no policies, everything else is own-row
or admin-only, and pack payments were correctly widened. Storage is private with own-folder
insert, a MIME allow-list, a size cap, and a server-side path re-check. Timezone maths is
Intl-based and correct throughout — this is the class of bug that quietly destroys booking
apps and it was clearly thought through. Google Calendar is best-effort everywhere, after
the DB write, so an outage never blocks a booking. `getUser()` (not `getSession()`) drives
every auth decision. The hold countdown is hydration-safe by seeding from `created_at`.
Receipt upload re-encodes iPhone HEIC and maps four distinct failures to actionable
Spanish. The scene has zero per-frame React state and zero per-frame allocations, correct
listener/rAF/GSAP cleanup, deliberate passive flags, and a frameloop that pauses offscreen
with a feature-detect that fails *open*. `sw.js` has no `fetch` handler, so there is no
stale-page class of bug. Admin surfaces its server load errors instead of swallowing them.
Contrast passes AA on every token pair checked. Voseo is consistent.

## 7. Mobbex — on hold

Not implemented; **required before enabling `NEXT_PUBLIC_MOBBEX_ENABLED`**:

1. **P0-class — the same silent-confirm bug as P0-2 lives in the webhook**
   (`mobbex-webhook/index.ts:138-152`): unchecked bookings UPDATE, guard only on
   `!== 'confirmed'`. Apply the identical fix (confirm first, `.in(status, CONFIRMABLE)`,
   alert the owner on failure, never send the confirmation blind).
2. **P0-class — the hardening is bypassable.** When the Mobbex API lookup fails for any
   reason, the code falls back to trusting the **IPN body's** status code (`:66-71`) — the
   very thing the June fix removed. Only the shared `?token=` then stands between an
   attacker and a free confirmed turno. Treat unverifiable as `pending` + admin alert.
3. The amount check compares against the **live** `services.price_ars` rather than the
   `payments.amount_ars` actually charged, so editing a price with a checkout open strands
   the payment; on mismatch it goes silently `pending` with **no** notification, and when
   `expected` is null the check is skipped entirely (i.e. it approves).
4. `create-payment` creates the checkout **before** the payment row and does not check that
   insert, so a failure hands out a pay URL for a row the IPN can never find: money in,
   nothing confirmed, no retry.
5. The booking is flipped to `awaiting_payment` merely for **returning a checkout URL** —
   no payment required — which is what makes abandoned checkouts squat a slot and a day
   forever, and makes `payment-panel.tsx:73-78` tell a user who never paid that their
   payment is being verified.
6. Chargeback/refund codes are ignored once a payment is `approved` (`:61` short-circuits).
7. The return URL carries no reference and the page does not poll, so a client who has just
   paid by card sits on "Verificando pago" until they manually refresh.

## 8. Roadmap

**Sprint 1 — booking funnel.** Hold-expiry check in `create-payment` + sweep on `/turno` so
the expired card and the Pay button can never co-exist; 6 OTP slots; Spanish error map +
"Reenviar código" with a 60 s cooldown; Turnstile reset + load-failure fallback; validate
`next` and surface `?error=auth`; carry the chosen slot through login; refetch `bookedDays`
client-side; explicit "usar crédito" choice; split `/mis-turnos`; status-specific next
actions on `/turno`; one `normalizePhone()`; fix `capitalize`; per-route metadata + OG.

**Sprint 2 — admin.** Pack rows in the verify queue; sync `upcoming` from props (or drop the
state); keyset pagination with surfaced errors; "Recientes" load-more; search/filter;
